Apakah mobile Sumber Sira memakai MVVM?

Jawab singkat: ADA — tapi di folder praktikum, bukan di aplikasi utama.
  • Aplikasi utama (Sumber Sira): View + AppState + ApiClient, memakai ChangeNotifier.
  • Contoh MVVM: lib/mahasiswa_mvvm/.
  • Contoh Clean Architecture: lib/mahasiswa/.
Catatan pembicara: Mulai dengan kalimat ini supaya dosen tahu kita jujur: paket provider dan go_router tidak ada di proyek.

Dua contoh arsitektur + satu aplikasi nyata

1. MVVM tradisional — mahasiswa_mvvm/ Model → Repository → ViewModel → View.
Cocok untuk penjelasan dasar MVVM.
2. Clean Architecture — mahasiswa/ Domain (entity + use case) → Data → Presentation.
Aturan bisnis dipisah dari UI.
3. Aplikasi utama Sumber Sira Tidak memakai kelas bernama Repository; perannya dijalankan ApiClient statis. Tidak ada provider/go_router (pubspec.yaml:9-25).
Struktur terbaru: lib/features/<fitur>/view + viewmodel — lihat docs/STRUKTUR_FEATURES.md.
Catatan: Tunjukkan folder di VS Code kalau bisa. Fokus slide ini: membedakan "contoh praktikum" dan "aplikasi sebenarnya".

Model & Repository: sumber data sederhana

Repository menyimpan data di memori (list), bukan HTTP. Itu sebabnya contoh ini mudah dipahami pemula.

// lib/mahasiswa_mvvm/repositories/mahasiswa_repository.dart:10-18
class MahasiswaRepository {
  final List<Mahasiswa> _data = [
    const Mahasiswa(nim: '001', nama: 'Andi'),
    const Mahasiswa(nim: '002', nama: 'Budi'),
  ];
  List<Mahasiswa> ambilSemua() => List.unmodifiable(_data);
}

Method lain: tambah() baris 21-23, hapus() baris 26-28, nimSudahAda() baris 31.

Catatan: List.unmodifiable mencegah View mengubah data secara langsung — semua perubahan lewat ViewModel.

ViewModel: tempat aturan & state

// lib/mahasiswa_mvvm/viewmodels/mahasiswa_viewmodel.dart:28-47
void tambah(String nim, String nama) {
  nim = nim.trim();
  nama = nama.trim();
  if (nim.isEmpty || nama.isEmpty) {
    pesanError = 'NIM dan nama wajib diisi';
  } else if (repository.nimSudahAda(nim)) {
    pesanError = 'NIM sudah digunakan';
  } else {
    repository.tambah(Mahasiswa(nim: nim, nama: nama));
    pesanError = null;
  }
  notifyListeners();
}
  • ChangeNotifier = kelas Flutter yang bisa memberi tahu widget kalau data berubah.
  • notifyListeners() = sinyal "gambar ulang UI" (baris 46).
Catatan: Tunjukkan juga pesanError di baris 25, dan daftar getter di baris 22.

Di aplikasi utama, "ViewModel"-nya bernama AppState

// lib/data/app_state.dart:14-16
class AppState extends ChangeNotifier {
  AppState._();
  static final AppState instance = AppState._();
}
  • Singleton: hanya satu objek untuk seluruh aplikasi (AppState.instance).
  • Isinya: tiket, booking, tarif, ulasan, pengaturan (app_state.dart:18-37).
  • View mendengar memakai ListenableBuilder, mis. eticket_screen.dart:72.
  • Data diambil lewat ApiClient (api_client.dart:98), bukan Repository abstrak.
Catatan: Ini poin paling penting: konsep mirip MVVM, tapi tidak memakai paket provider dan tidak ada ChangeNotifierProvider.

Ringkasan 3 kalimat + siap tanya jawab

  1. Ada MVVM? Ya, di lib/mahasiswa_mvvm/ (klasik) dan lib/mahasiswa/ (Clean Architecture).
  2. Aplikasi utama? View + AppState/controller + ApiClient; state memakai ChangeNotifier.
  3. provider/go_router? Tidak dipakai; yang ada http (pubspec.yaml:18).
